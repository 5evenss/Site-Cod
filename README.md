# ORBIT — за пределами привычного

Одностраничный сайт вымышленной студии цифровых экспериментов. Авторские визуальные концепции Flux и Signal — часть демонстрационного проекта, а не портфолио реальных заказчиков.

## Открыть прямо сейчас

Открой **`dist/index.html`** двойным кликом. Установка зависимостей, ключи, аккаунты и интернет не нужны: изображения, шрифты и код находятся в папке сайта.

Для работы через локальный сервер понадобится Node.js 20 или новее. В терминале из папки `website`:

```powershell
node scripts/serve.mjs
```

Открой **http://localhost:4173**. Остановка сервера — `Ctrl+C`.

Также доступны `npm start` и `npm run check`. В Windows PowerShell, если запуск `npm.ps1` запрещён, используй `npm.cmd start` и `npm.cmd run check`. `npm install` не требуется.

Если порт занят, задай другой:

```powershell
$env:PORT = 4174
node scripts/serve.mjs
```

## Что можно показать

- Hero «Веб-Технологии»: отдельный непрерывный фон из символов и собранная из микросимволов надпись. Возле курсора частицы физически разлетаются и пружинно возвращаются домой.
- Экран ORBIT с хромированной скульптурой, параллаксом и крупной типографикой.
- Появление секций при прокрутке и движущаяся типографическая лента.
- Две карточки концепций с подробностями в модальном окне.
- Лабораторию частиц: сфера, волна и спираль; четыре цвета; скорость; плавное превращение форм; реакция на курсор; пауза.
- Кнопку движения в шапке: она отключает анимацию на всей странице.
- Адаптивную версию с мобильным меню и управлением с клавиатуры.

Регистрация и серверная авторизация в эту версию не входят. Их можно добавить следующим этапом. Сейчас сайт не собирает пользовательские данные и не отправляет запросы на внешние сервисы.

## Настройки цифрового hero

Блок добавлен перед оригинальным экраном ORBIT. Его HTML — секция `#digital-hero` в `dist/index.html`, оформление — `dist/digital-hero.css`, анимация — `dist/digital-hero.js`. Остальные секции и их стили сохранены.

В начале **`dist/digital-hero.js`** находится объект `CONFIG`:

```js
const CONFIG = {
  text: "Веб-Технологии", // Название; обновляет и доступный HTML-заголовок.
  color: "#dddfe3", // HEX из шести цифр; цвет частиц и акцентов блока.
  particleCount: 1800, // Верхняя граница количества символов в надписи.
  speed: 2.4, // Множитель скорости фонового потока; 1 — исходная скорость.
  // Остальные настройки уже находятся в файле.
};
```

Измени нужные значения в существующем объекте и обнови страницу. При смене названия также обнови текст `#digital-hero-title` в HTML — это версия для браузеров с отключённым JavaScript.

Две системы имеют независимые частицы и настройки. `background` управляет потоком: `glyphs` — алфавит, `areaPerSymbol` — площадь на один символ (меньше значение — плотнее фон), `maxCount` — предел количества, `sizes`, `speeds` и `opacity` — размеры, диапазон скоростей и прозрачности. Символы непрерывно движутся слева направо и за правым краем переносятся за левый.

Текущая плотность: до 1 600 фоновых символов на большом экране, четыре размера 7/9/11/14 px. Для телефона действует отдельный минимум `mobileMinCount: 280`; число символов дополнительно зависит от площади экрана. Фон тусклее заголовка: диапазон непрозрачности 0,10–0,28 дополнительно уменьшается для дальних слоёв. Символы распределены по всей ширине и высоте блока. Поток ускорен в 2,4 раза; палитра hero — графитовый фон и светло-серые символы с лёгким свечением.

`textPhysics` управляет надписью: `glyphs` — её микросимволы, `pointerRadius` и `pointerForce` — область и сила отталкивания, `spring` — притяжение к исходной позиции, `damping` — затухание скорости. У каждой частицы есть `homeX/homeY`, текущие координаты и `velocityX/velocityY`. Прозрачность при наведении не меняется. Обычный текст рисуется только во временной маске; на видимом Canvas заголовок состоит исключительно из символьных спрайтов, без текстовой подложки.

Автоматического цикла распада больше нет: без курсора надпись постоянно собрана. Кнопка «Собрать заново» вручную запускает короткое пружинное возвращение из небольшого смещения; на паузе сразу возвращает символы на места. Фон при этом не перезапускается. Нижние подписи сохранены: подсветка отражает покой, отталкивание и возвращение. Отдельная пауза останавливает hero, общая кнопка движения — весь сайт. При `prefers-reduced-motion` показано статичное собранное название; явное нажатие «Запустить» включает эффект.

На экранах до 600 px название переносится по дефису или пробелу, бюджет частиц уменьшается через `mobileRatio`. Размер текста рассчитывается по ширине. Число фоновых символов зависит от площади экрана. `maxFps` ограничивает частоту отрисовки, `maxDpr` — разрешение Canvas (по умолчанию до 2). Символы заранее растеризуются в атласах с учётом DPR; на каждом кадре готовые спрайты копируются без расчёта blur и шрифта. Физика использует фиксированный шаг 1/120 секунды и ограничение времени после пропущенных кадров.

Сторонних библиотек нет. Обе системы используют один `requestAnimationFrame`, но разные состояния и функции обновления. В скрытой вкладке и вне экрана цикл останавливается; внутри видимого активного hero фон движется независимо от состояния надписи. Для установки на другой сайт нужно перенести секцию и подключить её два файла; обработчик общей кнопки ORBIT необязателен.

## На другом ноутбуке

Скопируй папку `website` целиком или скачай её из своего репозитория. Открой `dist/index.html` — сайт готов к показу даже без интернета. Для локального HTTP-сервера выполни ту же команду Node.js.

## Отдельный репозиторий GitHub — рекомендуемый вариант

Текущая папка находится внутри существующего проекта Spirit Swarm. Чтобы загрузить **только сайт**, сначала скопируй содержимое `website` в новую папку **за пределами Spirit Swarm**, например `D:\Projects\orbit-site`. В корне новой папки должны лежать `dist`, `scripts`, `package.json` и `.github`.

Создай пустой репозиторий на GitHub. В новой папке:

```powershell
git init
git add .
git commit -m "Create ORBIT interactive website"
git branch -M main
git remote add origin https://github.com/YOUR_NAME/YOUR_REPO.git
git push -u origin main
```

Вместо `YOUR_NAME` и `YOUR_REPO` подставь имя пользователя и название репозитория. Git может один раз попросить настроить имя и email автора коммитов.

### Публичная ссылка через GitHub Pages

Готовый workflow находится в `.github/workflows/pages.yml`.

1. В репозитории открой **Settings → Pages → Build and deployment → Source → GitHub Actions**.
2. Открой **Actions → Publish ORBIT to GitHub Pages → Run workflow**. После настройки последующие push в `main` запускают публикацию автоматически.
3. Дождись успешного выполнения. Ссылка на сайт появится в результате workflow и в разделе Pages.

В публикацию попадает только `dist`, без документации и инструментов. Все пути относительные: сайт работает по адресу с названием репозитория.

Workflow следует [официальной схеме GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages). Для бесплатного аккаунта используй публичный репозиторий.

### Если хочешь оставить сайт внутри Spirit Swarm

Перенеси файл `website/.github/workflows/pages.yml` в `.github/workflows/pages.yml` **корня репозитория**. GitHub не запускает workflow из вложенной папки. Workflow сам определит `website/dist`. Перед переносом проверь, нет ли уже файла с таким именем. При этом в репозитории останется весь проект Spirit Swarm; на Pages публикуется только сайт.

Никаких коммитов, push или публикаций при подготовке сайта не выполнялось.

## Структура

```text
website/
  dist/
    index.html           Секции, тексты, меню и диалог
    styles.css           Цвета, адаптивность и анимации
    app.js               Лаборатория и взаимодействия
    digital-hero.css      Изолированное оформление нового hero
    digital-hero.js       Поток символов, сборка текста, CONFIG
    assets/              Изображения, локальные шрифты и лицензия
  scripts/
    serve.mjs            Локальный сервер без зависимостей
    check.mjs            Проверка ссылок, файлов и синтаксиса
  .github/workflows/
    pages.yml            Публикация на GitHub Pages
  qa/
    VERIFICATION.md      Результаты проверки
    image-prompts.txt    Промпты исходных изображений
```

`dist` — редактируемый исходный сайт, а не временный результат сборки. Эту папку нужно включать в Git. Дополнительного шага сборки нет.

## Производительность

- Нет React, Three.js, тяжёлых библиотек анимации или CDN.
- Два изображения в WebP: примерно 389 КиБ суммарно. Шрифты загружаются локально.
- Canvas 2D рисует облако из 1 250 точек на компьютере и 700 на телефоне. При длительном падении частоты кадров число точек постепенно уменьшается.
- Плотность canvas ограничена до 1,5 на компьютере и 1,25 на телефоне.
- Частицы группируются по прозрачности; нет дорогих теней и соединения каждой точки с каждой.
- Единственный цикл `requestAnimationFrame` останавливается вне видимой области, в скрытой вкладке и на паузе.
- Скорость движения зависит от времени, а не частоты обновления монитора.
- Настройка системы `prefers-reduced-motion` отключает движение при первом открытии.

Счётчик в лаборатории измеряет частоту callback `requestAnimationFrame`, а не аппаратный вывод кадров. Реальный FPS зависит от браузера, устройства, дисплея и нагрузки.
