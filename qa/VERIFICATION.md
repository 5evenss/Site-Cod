# Проверка ORBIT

Дата: 4 октября 2026.

## Две системы частиц в цифровом hero

- Изменены `dist/digital-hero.js`, изолированный `dist/digital-hero.css` и документация. HTML, общие стили `styles.css` и исходный `app.js` сохранены без изменений; проверены контрольные суммы.
- После увеличения плотности на экране 1440 × 1000: 1 600 фоновых символов и 1 022 символа, образующих надпись. Фон использует четыре размера и меньшую яркость. Поток ускорен в 2,4 раза, палитра переведена в графитовую со светло-серыми символами. Неподвижные частицы текста точно сохраняют свои позиции между кадрами.
- Инструментирование Canvas подтвердило: видимый Canvas не вызывает `fillText`. Он отображает символьные спрайты, созданные заранее; текстовая маска существует только во временном Canvas.
- Все фоновые символы движутся вправо с разными скоростями, выход за границу переносит их налево. Повторная сборка надписи не сбрасывает позиции фоновых символов.
- Локальная реакция на курсор: из круга радиусом 25 px ушли все 31 частица; максимальное перемещение — 60,21 px. Альфа каждой частицы осталась прежней; частицы дальше 110 px от курсора не изменили координаты.
- Через 100 мс после ухода курсора возвращение ещё продолжается; после завершения координаты и прозрачность всех частиц точно совпадают с исходными.
- Проверены локальная пауза, остановка вне экрана и адаптивная вёрстка 320, 390, 600, 768 и 1440 px. Просмотрены собранная надпись, локальное отверстие и мобильная версия с DPR 2.
- Chrome headless, после увеличения плотности, время callback с отрисовкой: среднее 1,52 мс, 95-й перцентиль 1,80 мс. При замедлении CPU ×4: среднее 6,80 мс, 95-й перцентиль 7,70 мс. Это измерение JS и Canvas-команд, а не гарантия аппаратного FPS.
- Ошибок JavaScript не обнаружено; проверка синтаксиса и локальных файлов проходит.
- На мобильном устройстве проверены отталкивание при касании и возврат после отпускания, системное уменьшение движения и явное включение общей кнопкой. Открытие через `file://` работает без ошибок.

## Предыдущая версия цифрового hero (до замены физики)

- Новый изолированный блок перед экраном ORBIT; отдельные `digital-hero.css` и `digital-hero.js`.
- Визуально проверены поток символов, сборка, собранное название, распад и мобильный перенос по дефису.
- Chrome / Playwright: 320, 390, 600, 768, 1024 и 1440 px, включая DPR 2; горизонтальной прокрутки нет.
- Проверены локальная пауза, повторная сборка, общая кнопка движения, остановка вне экрана и явное включение при `prefers-reduced-motion`.
- После изменения подписи кнопки паузы текстовые мишени остаются на месте.
- Без JavaScript виден обычный HTML-заголовок; при `file://` Canvas работает без ошибок.
- Проверены переход к исходному экрану ORBIT, существующий диалог проекта и выбор формы в лаборатории.
- Ошибок JavaScript и ответов HTTP 4xx/5xx нет. `node scripts/check.mjs` теперь проверяет оба скрипта.
- До финальной корректировки планировщика среднее время отрисовывающего callback — 0,68 мс, 95-й перцентиль — 1,10 мс (2 200 частиц, 1440 × 1000). При CPU ×4 после корректировки 95-й перцентиль всех callback, включая дешёвые пропуски между кадрами, — 3,10 мс. Эти два замера имеют разные выборки и напрямую не сравниваются.
- Симуляция планировщика на 60, 75, 120, 144 и 180 Гц сохраняет среднюю частоту 60 кадров в секунду. Это проверка алгоритма, а не гарантия аппаратной производительности.

- Обе карточки, закрытие диалога через Escape, переход из концепции в лабораторию с выбором формы и цвета.
- При `prefers-reduced-motion: reduce` анимация выключена, содержимое доступно.

- Обработчик скрытия вкладки останавливает цикл и возобновляет его при возвращении; проверен имитацией события видимости.
- При эффективной ширине 720 CSS px и DPR 2 (геометрия окна 1440 px с масштабом 200%) горизонтальной прокрутки нет.

## Замер нагрузки

Chrome headless, 1 250 частиц, окно 1440 × 1000, по четыре секунды на режим:

| Режим             | Среднее время JS callback кадра | 95-й перцентиль |
| ----------------- | ------------------------------: | --------------: |
| Обычный           |                         0,24 мс |         0,40 мс |
| CPU throttling ×4 |                         1,06 мс |         1,30 мс |

Это время выполнения кода отрисовки, без гарантии времени композитинга и аппаратного вывода изображения. Headless-замер не доказывает частоту кадров на другом ноутбуке. Для демонстрации фактическую плавность нужно оценить в обычном браузере на целевом устройстве.

Скриншоты и машинный отчёт сохраняются локально в `qa`, но исключены из Git, чтобы не увеличивать репозиторий.
